# AGENTS.md

Operating rules for automated agents working in this repository.

For architecture, layout and build commands, read [`CLAUDE.md`](./CLAUDE.md).
This file is only about the things that will bite you *here* and not elsewhere.

---

## What this repository is

The library both `nex` (CLI) and the MCP server sit on top of. It holds the HTTP
layer, the session layer, and the credential handling for every ServiceNow call
either of them makes.

Two consequences worth internalising:

- **A bug here is a bug in three products.** There is no such thing as a local
  change to `comm/http/`.
- **It handles live credentials.** Not test fixtures — real sessions for real
  instances, including cleartext passwords for basic auth.

## Hard rules

### 1. Judge lint by delta, never by exit code

`npm run lint` **already fails on `main`** — roughly 1,190 pre-existing errors,
overwhelmingly `no-unsafe-*` in the older HTTP and AMB code. A green run is not
achievable and is not the goal.

Compare against the baseline instead:

```bash
npx eslint ./src -f json | python3 -c "import json,sys; print(sum(f['errorCount'] for f in json.load(sys.stdin)))"
```

Your change should leave that number **the same or lower**. Reporting "lint
fails" as though you caused it is worse than useless — it buries the signal that
you added four new errors.

### 2. Build before trusting `PublicApi.test.ts`

That test reads `dist/index.d.ts`, not `src/`. Two distinct traps:

- **No `dist/`** → the whole suite is `describe.skip`, so a new assertion passes
  vacuously and tells you nothing.
- **Stale `dist/`** → it fails for a change you did not make. This has already
  happened: a `dist/` several days old made a passing `main` look broken.

Run `npm run build` first, every time, before believing either outcome.

### 3. Anything you add to `src/exception/` becomes public API

The barrel is generated by `ctix` and post-processed by
`scripts/finalize-barrel.mjs`. `src/exception/` has no `index.ts` and is not in
`.ctirc`'s exclude list, so a new file there is exported automatically with no
further action — and removing it later is a breaking change.

To keep something internal, add it to `DROP` in `finalize-barrel.mjs`. The script
hard-fails if a `DROP` entry stops matching, so renames cannot silently
republish an internal.

After adding public API: `npm run build-index-export`, then assert it in
`test/unit/PublicApi.test.ts`.

### 4. Never static-import `@sonisoft/sn-credstore`

It is an **`optionalDependency`**, deliberately — core is a library, and making
it required would force a credential shim onto every consumer, including ones
that never opt in. It can genuinely be absent (`npm install --no-optional`, a
pruned install, a bundler that dropped it).

A static value import crashes those installs at load time. Use `import type`
(erased at compile time), or the dynamic, memoised pattern already in
`src/credentials/ensureShim.ts`.

For the same reason, do not `instanceof` its error classes — it ships dual
ESM/CJS, so two copies can exist. Duck-type on `code`/`remediation`, which is what
every consumer already does.

### 5. Never log or rethrow a credential

`src/util/redact.ts` exists because `RequestHandler` built `{auth: this._session}`
and logged it at debug on every request — `config.auth` **is** the session. That
wrote live cookies and tokens to `logs/app-debug.log`, which is why
`.gitleaks.toml` once had to allowlist `^logs/`.

- Redaction is wired into the shared logger as a Winston format, so structured
  metadata is handled for you.
- **Never interpolate a secret into the message argument.** `redactMessage` scrubs
  named patterns out of message text as a backstop, but it matches on the secret's
  NAME — it cannot know that an arbitrary token is a token. Pass it as a field, or
  better, do not log it. ScriptTracer logged `Session ID …: ${token}` at INFO and
  put a live session token on disk on every trace.
- Before rethrowing, run the error through `stripSecretsFromError`. It scrubs in
  place so `instanceof` and the stack survive.

The completion test is behavioural, not a unit assertion: log something, then read
the log file back and grep it. See `test/unit/util/LoggerRedaction.test.ts`, which
opts into file logging in a temp directory to do exactly that.

### 5a. Logging destination is the application's choice, never the library's

File logging is **off by default**. `src/util/LogConfig.ts` owns one process-wide
winston logger; `Logger` is only a named facade onto it. Three rules follow:

- **Never write to stdout.** The MCP server carries JSON-RPC there, and one stray
  `console.log` desynchronises the whole session. `test/unit/util/NoStdoutWrites.test.ts`
  scans `src/` for this, because no unit test executes every code path.
- **Never construct a logger with `transports: []`.** Winston `console.error`s the
  RAW info object when a logger has no transports, and does so *before* the format
  chain runs — so redaction never happens. "Off" is a transport with `silent: true`.
- Configuration is process-global because ~43 field initializers do
  `private _logger = new Logger("Name")` with no arguments. Do not try to thread
  options through manager constructors.

### 5b. The permission gate has exactly one enforcement point

`RequestHandler.getRequestConfig`, beside the cross-instance guard. Do not add a second.

- **Never gate on the HTTP verb.** It lies both ways: `installStoreApplication` and
  `updateStoreApplication` mutate via GET, `exportUpdateSet` GETs with
  `sysparm_delete_when_done`, and `ServiceNowProcessorRequest` POSTs to *read*.
  Classification lives in `policy/internal/Classify.ts` and keys on path **and query
  params**.
- **Adding a mutating endpoint that travels as a GET means adding a FLOOR rule.** There
  is no static check for this — nothing can know that `/api/sn_appclient/.../install`
  mutates. The audit log ("Permitted by policy", with the deciding layer) is the
  backstop; a write permitted for a surprising reason shows up there.
- **A `requires` declaration can correct a wrong default but never lowers a floor rule**,
  and cannot move a floor match off `target: 'instance'` — otherwise declaring
  `target: 'local'` would be a way to opt out of the gate.
- **Refusals are branded with `Symbol.for`, never a class.** Two copies of this package
  in a consumer's `node_modules` break `instanceof` silently, and
  `BackgroundScriptExecutor` would then stop recognising a refusal and run the script
  via `sys_trigger` anyway. Use `isPolicyRefusal`.
- **Anything that catches broadly around a gated call must re-throw refusals.**
  `executeScriptAuto` is the cautionary tale: its `catch` fell back to a scheduled job,
  turning a refusal into a deferred execution.

### 6. Force state in tests; never wait on the clock

`test/unit/comm/http/ActiveSessionRegistry.test.ts` records a real CI flake
caused by a 1 ms TTL that expired between two calls. The fix was not a longer
sleep — it was mutating the timestamp directly:

```ts
session!.lastAccessedAt = new Date(Date.now() - ttlMs * 2)
```

Same for concurrency: drive a manually-resolved deferred so two operations are
genuinely in flight, rather than hoping the scheduler interleaves them.

### 7. Guard new deep imports into the SDK

`@servicenow/sdk-cli-core`'s package root is unusable (its `exports` map rejects
the paths we need), so this repo imports from `dist/**` directly. That is the
brittlest coupling in the codebase and it is pinned by version.

`test/unit/comm/http/sdkDeepImports.test.ts` performs a real dynamic import of
each one. **If you add a deep import, add a case there** — it is the only thing
that will catch a path that disappears in an SDK upgrade.

## Conventions that are easy to get wrong

- `private _name`, not `#private` (226 occurrences vs 16, all four in the HTTP and
  auth layers use the underscore form).
- Imports omit the file extension in `src/`; `tsc-alias` appends `.js` at build.
  The generated barrel is the exception and uses explicit `.js`.
- `eslint` runs on `./src` only. `test/` is never linted, which is why
  `(x as any)._private` is pervasive there and fine.
- Commits are conventional (angular preset). `feat` cuts a minor, `fix` a patch,
  and semantic-release publishes on merge to `main` — so the commit type you
  choose is a release decision, not a label.

## Before you open a PR

```bash
npm run build        # required — see rule 2
npm run test:unit
npx eslint ./src -f json   # compare the count, see rule 1
```

State the lint delta explicitly rather than the raw number. A reviewer cannot
tell 1194 from 1198 without being told which direction it moved.
